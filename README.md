# 数字化献血志愿者招募平台

面向**个人献血者、团体单位联系人、招募科 / 体采科工作人员、系统管理员**的数字化献血招募与服务平台，可本地运行、可页面演示，覆盖《需求说明书》全部业务模块。外部系统（无纸化签署、采供血业务系统、微信公众号、智慧招募呼叫系统）以 **mock 接口 + 调用日志** 方式实现，其余业务逻辑（RBAC 权限、预约状态机、双表签署、排班、积分、消息、报表、系统管理）**全部真实落库实现**。

技术栈：**FastAPI + SQLAlchemy + SQLite + Vue3 + Element Plus + ECharts + Pinia**，后端运行于 Conda 环境 `xueye`（Python 3.11）。

---

## 一、目录结构

```
xueye/
├── backend/                 # FastAPI 后端
│   ├── app/
│   │   ├── core/            # 配置、数据库、安全、依赖、积分、审计、常量
│   │   ├── models/          # SQLAlchemy 数据模型
│   │   ├── schemas/         # Pydantic 模型
│   │   ├── routers/         # 各业务模块接口
│   │   ├── seed.py          # 演示数据初始化
│   │   └── main.py          # 应用入口（启动建表 + seed）
│   ├── environment.yml      # Conda 环境定义
│   └── requirements.txt
└── frontend/                # Vue3 + Element Plus 前端
    └── src/
        ├── api/             # axios 封装
        ├── router/          # 路由 + 登录/角色拦截
        ├── store/           # Pinia 状态管理
        └── views/           # 页面（user / admin / group / 叫号大屏）
```

## 二、环境准备与启动

### 1. 后端（FastAPI）

```bash
conda create -y -n xueye python=3.11
conda activate xueye
cd backend
pip install -r requirements.txt
python -m app.seed                       # 首次初始化演示数据（可选，启动时也会自动 seed）
uvicorn app.main:app --reload --port 8000
```

- 接口文档（Swagger）：http://127.0.0.1:8000/docs
- 启动时自动建表并写入：管理员/工作人员账号、采血点、字典、组织机构、系统参数、评价模板、礼品、示例消息、团体申报与活动等。

### 2. 前端（Vue3）

```bash
cd frontend
npm install
npm run dev   # 默认 http://127.0.0.1:5173
```

前端通过 Vite 代理把 `/api` 转发到后端 `http://127.0.0.1:8000`。

## 四、角色与权限（RBAC）

| 角色 | 主要权限 |
| --- | --- |
| 个人献血者 `user` | 注册登录、个人信息维护、健康信息填写、预约管理、双表签署、评价、反馈、积分查询与兑换、消息查看、个人献血信息查询 |
| 团体单位联系人 `group_contact` | 团体申报、申报状态查看、团体活动查看、宣传海报查看、团体预约信息查看 |
| 招募科工作人员 `recruiter` | 团体受理、预约统计、海报生成、消息推送、反馈处理、招募计划管理 |
| 体采科工作人员 `collector` | 排班管理、现场预约查看、双表审验、采血状态查看 |
| 系统管理员 `admin` | 用户管理、角色权限、组织机构、参数配置、模板配置、日志查看 |

后端通过 `get_current_user / get_current_staff / get_current_admin` 等依赖做服务端鉴权；前端通过路由 meta + Pinia 角色做访问控制。个人数据/团体数据按归属隔离。

## 五、功能模块与实现状态

| 9 | 宣传海报管理 | 海报模板维护、按单位/时间/地点快速生成、模拟微信推送给联系人 |
| 10 | 排班计划管理 | 团体献血周/月计划自动生成+发布、体采人员排班自动生成（人数/车辆/司机/注意事项）+审核发布、按人员/点位/车辆查询 |
| 11 | 身体异常反馈 | 勾选+描述提交，状态：已反馈/正在联系处理/已解决，工作人员处理 |
| 12 | 献血过程评价 | 评价模板管理（全血/成分血指标、启停）、评价送积分（同次仅一次）、统计分析 |
| 13 | 个人献血信息查询（嵌入·mock） | 电子献血证编号、累计献血量、献血足迹、血液检测结果、血液使用情况、积分 |
| 14 | 积分兑换 | 积分余额/来源/明细、礼品目录、兑换申请与状态流转（待处理/处理中/已兑换/已取消）、取消退还 |
| 15 | 消息推送 | 7 类消息类型、普发/定向（按角色/手机号）、新增/编辑/发布/撤回/删除、阅读状态与已读统计、模拟微信群发 |
| 16 | 系统管理 | 组织机构 CRUD、工作人员账号管理（启停/重置密码）、角色权限矩阵、系统参数、选项字典、操作日志审计 |
| 17 | 外部系统交互（mock） | 无纸化签署 / 采供血业务系统 / 微信公众号 / 智慧招募呼叫，统一记录 `external_logs` |

## 八、边界说明

外部系统（微信、无纸化签署、采供血业务系统、智慧招募呼叫系统）采用 **mock 接口 + 调用日志** 实现，用于证明系统结构与数据闭环完整；不含真实第三方对接与线上部署。其余业务逻辑均真实实现并持久化于 SQLite。
