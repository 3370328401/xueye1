# 数字化献血志愿者招募平台 — 完整需求 vs 现有 MVP 差距分析与实施计划

> 背景：现有代码是「MVP 第一版」，覆盖完整需求说明书的一个子集。本文件对照完整需求说明书做差距分析，并给出分阶段实施计划。

## 一、现有 MVP 已实现（基线）

| 模块 | 现状 |
| --- | --- |
| 注册登录 | 手机号+密码 + JWT；区分 user/admin 两种角色 |
| 个人信息 | 增改查 |
| 健康征询表 | 填写/提交，提交后预约状态自动流转 |
| 献血预约 | 新增/我的预约/详情/取消；管理端列表+改状态 |
| 团体申报 | 提交 / 手机号查询 / 管理端受理改状态 |
| 异常反馈 | 提交 / 管理端处理 |
| 献血评价 | 提交 / 管理端查看 |
| 统计图表 | 卡片 + 4 个 ECharts（状态分布/趋势/类型/反馈） |
| 外部接口占位 | 4 个 mock（电子签署/采供血/微信/智慧招募）+ 调用日志 |

## 二、完整需求新增 / 需改造的部分

### A. 需改造（已有但不符完整规范）
1. **角色体系**：现仅 user/admin。完整需求有 5 类角色：个人献血者、团体单位联系人、招募科、体采科、系统管理员 → 需引入角色/权限模型（RBAC）。
2. **预约状态机**：现状态名与完整需求的 6 态不一致（待填双表及签字确认 / 双表已填且确认 / 待现场采血 / 正在现场采血 / 已完成现场采血 / 作废），且需按规则流转、禁止用户改关键状态。
3. **登录方式**：新增手机验证码登录、微信授权登录（MVP 可 mock 验证码/微信）。
4. **评价**：新增评价模板管理（全血/成分血）、评价送积分。
5. **团体**：新增团体活动创建 + 团体献血业务流程号、团体分类统计、按年度历史。

### B. 全新模块（完整需求有、MVP 完全没有）
6. **双表（个人信息登记表 + 健康征询表）自动生成 + 电子签署 + 签署历史 + 现场审验**
7. **预约叫号显示**（排队顺序/前方人数/按采血点·类型分类显示）
8. **预约提醒**（预约前推送提醒）
9. **团体宣传海报管理**（模板维护 + 快速生成 + 推送）
10. **排班计划管理**（团体献血周/月计划 + 体采人员排班表 + 审核发布 + 查询）
11. **积分兑换**（积分展示/来源/变动记录 + 礼品兑换 + 兑换状态）
12. **消息推送**（多消息类型 + 普发/定向 + 管理 + 个人端展示）
13. **个人相关信息查询嵌入**（血液检测结果 / 献血足迹 / 电子献血证 / 血液使用 / 积分 — 来自采供血系统，MVP 用 mock）
14. **系统管理**（组织机构 / 用户 / 角色权限 / 系统参数 / 选项字典 / 操作日志审计）
15. **统计报表**（6 类报表 + 导出）
16. **业务规则**（献血间隔校验、双表签署规则、状态流转规则、团体数据隔离、评价积分规则、消息推送规则）
17. **非功能**（操作日志审计、外部接口异常友好提示、防重复提交等）

## 三、关于"真实对接 vs 模拟"

完整需求描述的是生产系统（真实微信公众号、真实电子签署、真实采供血系统对接）。本地可运行的 Demo 无法做真实第三方对接，建议：
- 外部系统（微信/电子签署/采供血/智慧招募）继续用 **mock 接口 + 调用日志** 实现，保证流程闭环和结构完整，真实对接留接口位。
- 其余业务逻辑（角色权限、双表、排班、积分、消息、报表、系统管理）**全部真实实现**并落库。

## 四、分阶段实施计划（建议顺序）

- **P1 基础改造**：RBAC 角色权限模型 + 5 类角色 + 预约状态机对齐 + 操作日志 + 选项字典。
- **P2 双表与签署**：双表自动生成、电子签署（mock 签署服务）、签署历史、现场审验、献血间隔校验。
- **P3 团体闭环**：团体活动创建+流程号、宣传海报模板/生成/推送、团体分类与年度统计。
- **P4 排班计划**：团体周/月计划、体采排班表、审核发布、查询。
- **P5 服务闭环增强**：评价模板+评价积分、积分兑换、叫号显示、预约提醒。
- **P6 消息与查询**：消息推送（普发/定向）、个人信息查询嵌入（检测结果/足迹/献血证/血液使用，mock）。
- **P7 系统管理与报表**：组织机构/用户/角色权限/参数/字典/日志后台 + 6 类统计报表 + 导出。
- **P8 非功能与验收**：数据隔离、防重复提交、异常友好提示、端到端走查 + 文档更新。

每阶段都会：补全后端模型/接口 + 前端页面 + 种子数据 + 本地联调，并按需求的验收标准自测。
